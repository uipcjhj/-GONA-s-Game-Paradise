# M3 — 고나의 아슬아슬 탑 (`tower`)

구현: `src/mini-game-land/games/tower/` · 물리 `physics.ts`(matter-js 를 이 파일에만 가둠) · 진행 `game.ts`(React 무관, 헤드리스 테스트) · 규칙 `logic.ts` · 화면 `View.tsx`.
M1 공통 시스템(타이머·점수·콤보·목숨·일시정지·결과·기록)과 M2 스킨 슬롯 구조를 그대로 쓰며, 자유 플레이/랜덤 챌린지가 같은 모듈을 마운트합니다.

## 1. matter-js 필요성 검증 (승인 조건)
`tools/spike-tower-physics.mjs` 로 확인. **결론: 필요하며 채택**.
- 기울기·무게중심·굴러떨어짐·연쇄 붕괴는 강체 물리가 있어야 성립 → 직접 구현은 비현실적.
- **단, 기본 설정은 높은 탑이 무너짐**(18개 중 4~7개만 생존). 아래 설정에서 18/18 생존·결정적:
  | 설정 | 생존 |
  | --- | --- |
  | 기본(1/60, 반복 6/4) | 7/18 |
  | 반복만 12/10 | 5/18 |
  | 서브스텝 2 | 4/18 |
  | **서브스텝 3 + 반복 10/8** | **18/18** |
  | **서브스텝 2 + 슬립(sleeping)** | **18/18 (속도 0)** |
  | 서브스텝 2 + 중력 0.7 | 18/18 |
- 채택 설정: **서브스텝 3 · 반복 10/8 · 슬립 켬**. `physics.test.ts` 가 이 값을 고정해 보호(바꾸면 테스트 실패).
- 성능: 0.014ms/업데이트(서버). 조각 ≤20개라 모바일에서도 여유. 번들: 탑 청크 98.9kB(gz 31.9kB)이며 **탑을 플레이할 때만 지연 로딩**.
- 추가 의존성: `matter-js`(MIT), `@types/matter-js`(개발 전용 타입).

## 2. 게임 방식
- 접시 위에 간식을 쌓아 **깃발(목표 높이)** 에 닿고 **1.2초 버티면 성공**.
- **조작(모바일 우선)**: 화면을 밀면 조각이 **1:1 로 따라오고(상대 이동 — 손가락이 조각을 가리지 않음)**, **손을 떼면 낙하**. 회전: ⟳ 버튼, 또는 **한 손가락으로 잡은 채 다른 손가락으로 탭**(놓아도 낙하 안 함). 교환: ⇄ 버튼(다음 조각과 맞바꿈, 횟수 제한).
- **실패**: 떨어뜨린 조각 수가 한도(L1~8: 4번, L9~10: 3번)에 닿거나, 조각 예산 소진, 제한시간 종료.
- 낙하 → 닿음 → 가라앉기(0.3초 안정 또는 최대 2.6초) → 평가 → 다음 조각. 가라앉는 동안은 다음 조각을 놓을 수 없음(연타 방지).

## 3. 손맛 설계
- 착지 시 **화면 흔들림(충격 크기 비례) + 효과음(thud) + 진동(Android)**, 놓을 때 효과음(drop).
- 평가 알림: **완벽(+50 보너스) / 안정 / 아슬아슬(흔들림) / 떨어짐** + 콤보 표시.
- 카메라: 탑이 오르면 부드럽게 따라 올라감(프레임 독립 보간). 정수 배율 k = floor(스테이지 폭÷180)로 도트 선명도 유지.
- **무게중심(CoM) 표시**: 탑 전체의 무게중심 ▲ 이 접시 안이면 초록, 밖이면 빨강(L1~6). **낙하 안내선**(조각 아래 그림자 기둥, L1~4).
- 조각마다 **무게 눈금**(●~●●●)이 있어 무거운 건 아래로 두는 전략이 보임.

## 4. 점수
정확히 M1 공통 규칙을 따름: 완벽 150 · 안정 100 · 흔들림 50 · 떨어짐 0 (콤보 배수 ×(1+0.1·연속) 적용, 안정/완벽만 콤보 이어짐), 클리어 +300 + 공통 시간 보너스(챌린지는 라운드 배율).

### 측정 과정에서 고친 설계 문제
1. 콘의 꼭대기가 점이라 위에 못 얹음 → 꼭대기에 폭 14 평면.
2. 도넛(반지름 15 팔각형)의 윗면이 11px 로 좁아 연쇄 붕괴 → 폭 40 의 납작한 8각형.
3. 케이크 조각(쐐기)이 한쪽 끝이 점인 얇은 삼각형(두께 7)으로 퇴화 → 두께 10~22 사다리꼴 쐐기. (카탈로그 테스트가 잡아냄)
4. 바람이 탑을 밀어 슬립을 꺼야 했음 → 떨어지는 조각만 날리도록 변경.

## 7. 알려진 한계 · 후속
- 임시 도형(색 다각형+무게 점)만 사용. 최종 에셋 시 `PieceArt` 가 `piece.kind`/`bbox` 로 스프라이트를 고르도록 교체.
