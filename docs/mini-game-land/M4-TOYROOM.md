# M4 — 고나의 엉망진창 장난감방 (`toyroom`)

구현: `src/mini-game-land/games/toyroom/` · 규칙 `engine.ts`(순수) · 퍼즐 생성 `generator.ts` · 검증용 솔버 `solver.ts` · 진행 `game.ts`(React 무관) · 난이도 `logic.ts` + **설정 테이블 `tuning.ts`** · 화면 `View.tsx`.
M1 공통 시스템(타이머·점수·콤보·목숨·일시정지·결과·기록)과 M2 스킨 슬롯 구조를 그대로 쓰며, 자유 플레이/랜덤 챌린지가 같은 모듈을 마운트합니다.

## 1. 규칙 — "같은 그림을 탭하는 게임"이 아니라 이동 순서와 공간을 고민하는 퍼즐
- 선반은 **가로 한 줄**. **아무 장난감이나** 집어서 **다른 선반 맨 오른쪽**에 놓습니다 = 이동 1번(제한 있음).
- 집으면 오른쪽 장난감이 **왼쪽으로 당겨져(압축)** 양옆이 붙습니다. 같은 종류 **3개가 이어지면 세트 정리**.
  → 한 수가 "빼서 붙이기"와 "놓아서 완성하기"를 동시에 할 수 있음. 칸이 모자라므로 무엇을 어디로 옮길지 순서가 중요.
- **연쇄 반응**: 한 이동에서 연달아 정리되면 `연쇄 ×n`(점수 ×1.5, ×2.0, ×2.5). 예: 선반 A 에서 가운데 장난감을 빼 세트가 완성되고(A 정리), 그 장난감을 선반 B 끝에 놓아 또 세트가 완성(B 정리) = 연쇄 2. 정리로 양옆이 다시 붙어 같은 선반에서 이어지는 연쇄도 지원(칸 7↑ 필요, 엔진 테스트).
- **특수 요소**: ★ 별 장난감(아무 종류로 쓰임, L3~) · 🔒 잠긴 칸(세트를 정리할수록 순서대로 열림, L4~) · 고정 장난감(집을 수 없고 세트에만 쓰임, L5~).
- **조작(모바일)**: 장난감 탭(선택, 위로 떠오름) → 옮길 선반 탭. 선택하면 이동 가능한 선반은 초록, 불가한 선반은 빨강으로 표시. 같은 장난감 다시 탭 = 선택 해제, 다른 장난감 탭 = 선택 교체. 선반 한 줄이 통째로 터치 영역(높이 44~84px).
- **되돌리기**(횟수 제한, 이동 수도 되돌려 줌) · **처음부터**(같은 퍼즐). 되돌렸다 같은 이동을 다시 해도 **점수는 한 번만**(점수 복사 방지).
- **승리**: 모든 장난감 정리. **실패**: 이동 제한 소진 / 놓을 곳이 전혀 없는 막힘 / (챌린지) 시간 종료. 마지막 이동으로 완성하면 성공이 우선.

## 2. 풀 수 있는 퍼즐 생성·검증 (운에 의존하지 않음)
- **역방향 생성**: 완성(전부 정리) 상태에서 거꾸로 거슬러 올라가며 한 단계(= 정답 풀이의 이동 1번)씩 장난감을 배치. 패턴: `single`(끝에 놓아 완성) · `source`(가운데를 빼서 완성) · `double`(한 번에 두 곳 정리) · `cascade`(같은 선반 연쇄) · `relocation`(세트와 무관한 준비 이동).
- **검증**: 각 단계의 후보를 **실제 규칙 엔진으로 앞으로 실행**해 직전 상태와 정확히 같을 때만 채택 → 생성된 정답 풀이가 항상 합법이고 전부 정리됨. 마지막에 처음부터 끝까지 한 번 더 재생 검증. 퍼즐과 함께 **정답 풀이(witness)** 를 반환(힌트·검증용).
- **이동 제한 = 정답 풀이 길이(par) + slack**(레벨 설정). 3별 = par 이하, 2별 = par+slack/2 이하.
- 자리가 빠듯한 설정에서 드물게 실패하면 시드를 바꿔 재시도 → 그래도 안 되면 준비 이동을 줄여 생성(항상 퍼즐 반환).
- **독립 솔버 교차 검증**(너비 우선 탐색, 테스트·개발 전용): L1~3 은 솔버가 최소 풀이를 찾아 par 이하임을 확인하고(par−최적 평균 0.0~0.8), "최소보다 한 수 적은 한도에는 해가 없음"도 확인(이동 제한이 실제로 의미 있음). L4 는 21/30 해결, par−최적 평균 2.0 — **L4 이상에서는 최적해가 par 보다 짧을 수 있음**(준비 이동이 불필요한 경우). L5 이상은 상태 공간이 커 BFS 로 확인 불가 → 생성 시 재생 검증(witness)이 보증.

## 4. 점수
세트 정리 100 × 연쇄 배수(1.0 / 1.5 / 2.0 / 2.5) → ctx.addScore 가 콤보 배수 적용. 콤보 = 연속으로 세트를 정리한 이동 수. 클리어 +300 + 남은 이동 × 20 + 챌린지는 공통 시간 보너스·라운드 배율. 챌린지 제한시간 = 25 + 7×세트 초(자유 플레이는 무제한).

## 5. 연출·조작감
- 이동 결과를 **단계(lift → pop → clear → place → pop → clear)** 로 재생: 정리되는 장난감이 커졌다 사라지고, 오른쪽이 당겨짐. 점수·상태는 이동 즉시 확정되고 재생 중에는 입력만 잠금(연타로 꼬이지 않음).
- 알림: `정리! +100` · `연쇄 ×2! +250` · `콤보 ×n` · `칸이 열렸어요!` · `자리가 없어요` · `고정된 장난감은 못 옮겨요` · `아직 잠긴 칸이에요`.

## 6. 스킨 슬롯 (임시 그래픽은 모두 교체 가능)
`games/toyroom/slots.ts`: `Backdrop`(방 배경) · `ShelfFrame`(선반 틀·잠긴 칸, 상태: idle/source/target/blocked) · `ToyArt`(장난감 한 개: 종류 0~5·별·고정, 상태 idle/lifted/pop) · `Meter`(이동·세트·되돌리기) · `Feedback`(알림). 버튼은 공통 `ButtonFace`. 점검용 data-*: `[data-testid=board]` (`data-shelves/caps/moves/left/limit/par/sets/total/undo/selected/busy/status`) — `?dev=1` 일 때만 `data-solution`(정답 풀이)도 노출.
