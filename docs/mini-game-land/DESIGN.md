## 2. 충돌 가능성 (명시)

1. **섬 이름 중복** — `minigame-paradise / 미니게임천국` 과 `GONA's Mini Game Land` 는 사실상 같은 자리. 연결하려면 `islands.ts`(상태·URL·이름) 수정이 필요 → **승인 전 수정 안 함**. 개발 중에는 `/mini-game-land/` 주소로만 접근.
2. **`vite.config.ts` 단일 입력** — 다중 페이지 입력을 추가해야 함(추가만, 기존 동작 불변). 승인 후 이 한 파일만 건드림.
3. **전역 CSS 충돌** — 별도 HTML 진입점으로 만들면 `styles.css` 가 로드되지 않아 충돌 원천 차단. 새 코드는 `mgl-` 접두 + CSS 변수 토큰.
4. **tsc 가 `src/**` 전체 검사** — 새 코드도 같은 strict 규칙을 통과해야 `npm run build` 성공. 새 코드의 타입 오류가 기존 배포 빌드를 깨뜨릴 수 있으므로 브랜치 단계에서 항상 build 통과 확인.
5. **main 병합 = 자동 배포** — 병합하면 `/mini-game-land/` 가 (섬이 `soon` 이어도) 주소만 알면 공개됨. 공개 시점은 승인 후 결정.
6. **에셋 부족** — 고나는 정지 1프레임뿐, 간식·장난감·친구 캐릭터 에셋 없음. CLAUDE.md 규칙상 CSS/Canvas 로 승인 에셋을 대체하는 것은 금지, 이미지 생성 도구도 임의 사용 금지 → §7 목록 확정 전에는 **개발용 임시 도형**만 사용(출시 에셋 아님을 코드에 명시).
7. **브랜치 푸시** — 원격에 `feature/*` 없음(이름 충돌 없음). 다만 이 세션의 푸시 허용 브랜치는 `claude/elegant-ritchie-0djg0u` 로 지정돼 있어, `feature/mini-game-land` 의 **원격 푸시는 아직 하지 않았습니다**(로컬 생성만). 푸시해도 되는지 알려 주세요.
8. **저장소 한계** — localStorage 는 iOS Safari 에서 7일 미사용 시 삭제될 수 있음, 사생활 보호 모드에서는 쓰기 실패 가능 → 메모리 폴백 + "기록이 기기에만 저장됨" 안내. 서버 랭킹은 범위 밖.
9. **상업 배포 고려** — 라이선스: React/Vite(MIT), Galmuri(OFL, 상업 사용 가능), matter-js(MIT, 제안). 고나 IP 는 사용자 소유로 가정. 참고하는 장르(분류·쌓기·정리 퍼즐)는 일반 메커닉이며 타 게임의 이름·그래픽·UI 는 쓰지 않음.

### 3.2 게임 모듈 계약 (두 모드가 공유하는 유일한 접점)

```ts
interface MiniGameModule<P> {
  id: 'sort' | 'tower' | 'toyroom';
  meta: { title: string; tagline: string; howTo: string[]; maxLevel: number };
  difficulty(level: number): P;                       // 순수 함수 → 테스트 가능
  timeLimitSec(level: number, mode: Mode): number | null;
  load(): Promise<{ default: ComponentType<GameViewProps<P>> }>;   // 게임별 코드 분할
}
interface GameViewProps<P> { params: P; level: number; seed: number; ctx: GameContext }
interface GameContext {
  paused: boolean;
  addScore(points: number, at?: { x: number; y: number }): void;
  setCombo(n: number): void;
  onFrame(cb: (dtMs: number) => void): () => void;    // 공통 루프, 일시정지 중 호출 안 됨
  listen(target: EventTarget, type: string, fn: EventListener, opts?: AddEventListenerOptions): void; // 자동 해제
  sfx(name: string): void;
  finish(r: { outcome: 'clear' | 'fail'; stats?: Record<string, number> }): void;  // 멱등
}
```

게임은 **모드를 모릅니다**. 목숨·다음 게임 선택·기록 저장은 전부 Shell/session 이 담당 → 자유 플레이와 챌린지가 같은 모듈을 그대로 씀.

### 3.3 공통 시스템

| 기능 | 설계 |
| --- | --- |
| 타이머 | Shell 이 소유. `performance.now()` 델타 누적, 일시정지 중 정지. 게임이 `timeLimitSec` 를 선언(없으면 null). HUD 막대 + 마지막 5초 경고 |
| 일시정지 | 버튼 + `visibilitychange/pagehide/blur` 자동 정지. 해제 시 3-2-1. 정지 = 루프·물리·오디오 동시 정지 |
| 점수 | 게임이 원점수 보고 → `scoring.ts` 가 콤보·시간 보너스 적용. 챌린지는 라운드 배율 ×(1+0.05·(라운드−1)), 상한 ×2 |
| 난이도 | 게임별 `difficulty(level)` + 공통 시간 스케일. 레벨은 정수, 상한(maxLevel) 이후는 시간만 압축 |
| 결과 화면 | 하나의 `ResultScreen` — 결과, 점수 내역, NEW RECORD, [다음/다시/메뉴] |
| 저장 | 키 `gmgl.v1` (`{games:{id:{bestScore,bestLevel,plays}}, challenge:{bestScore,bestRound}, settings}`), 스키마 버전·검증·try/catch. `gameId = 'mgl.sort'` 식으로 `ScoreEntry` 와 호환 |
| 누수·중복 방지 | ① rAF 는 Shell 에 **하나**, ② 모든 리스너는 `ctx.listen`/Disposer 로만 등록, ③ 한 번에 게임 하나만 마운트(`key=roundId`), ④ StrictMode 이중 실행에서도 안전하게 설계(이펙트 멱등), ⑤ 라운드 전환마다 오디오 노드·물리 월드 `dispose()` |
| 모바일 | Pointer Events + `touch-action:none`, 더블탭 확대·고무줄 스크롤·텍스트 선택 차단, `100dvh` + safe-area, 터치 영역 44px↑, 오디오는 첫 터치에서 unlock(iOS), 무음 스위치/음소거 토글 저장 |
| 해상도 | 논리 폭 180px 고정, 폰은 정수 ×2(360px), 큰 화면 ×3 상한. 세로는 가용 높이만큼 가변 → 393×636 / 390×844 모두 도트 선명도 유지 (스크린샷으로 검증) |
| 게임별 개성 | 팔레트·배경·효과음 뱅크는 게임마다 독자 설계. 공통 UI 는 테마 토큰(CSS 변수)으로 색만 바뀜 |

### 3.4 자유 플레이 / 랜덤 챌린지

**자유 플레이** — 게임 선택 → (첫 방문 방법 안내) → 레벨 1(또는 도달한 최고 레벨까지 선택)부터 시작 → 클리어 시 레벨+1로 이어짐 → 실패하면 결과 화면에서 [같은 레벨 재도전 / 처음부터 / 메뉴]. 목숨 없음(재도전 자유). 기록: 게임별 최고 점수·최고 레벨.

**랜덤 챌린지** — 목숨 3, 라운드 반복.
- 게임 선택: **셔플백**(3종을 한 번씩 섞어 소진) + 직전과 같은 게임 연속 금지 → 편중 방지, 첫 3라운드에 3종 모두 체험.
- 라운드 레벨 `= 1 + floor((라운드−1)/2)` (게임별 maxLevel 로 클램프), 제한시간 ×max(0.6, 1−0.03·(라운드−1)).
- 성공: 점수(+라운드 배율). 실패: 목숨 −1, 해당 라운드 0점, 다음 라운드로. 목숨 0 → 종료·종합 기록 저장(최고 점수·도달 라운드).
- 라운드 시작 1.2초 "다음 게임" 카드(탭하면 건너뜀). 도중 나가기 = 즉시 종료·기록 저장.
- (선택) 5연속 클리어마다 목숨 +1(최대 5) — §8 결정 필요.

## 4. 미니게임 3종 상세 규칙

### A. 고나의 편가르기 대소동 (`sort`) — 빠른 판단 분류
- **화면**: 위 규칙 배너("리본 있으면 ◀ / 없으면 ▶"), 가운데 현재 카드(고나 친구 1명 + 다음 카드 미리보기 1장), 아래 분류함 2~3개.
- **조작**: 카드를 좌/우(3분류는 위)로 **스와이프**(거리 40px 또는 속도) 또는 큰 분류함 버튼 **탭**. 둘 다 지원(접근성).
- **캐릭터**: 속성 4축 — 색(4) · 머리 장식(리본/모자/안경/없음) · 들고 있는 것(2~3) · 크기(대/소). 레벨이 오르면 활성 축이 늘어남.
- **규칙 진행**: L1–3 단일 조건 → L4–6 AND/OR 복합 → L7–9 "아니면(NOT)"·3분류 → L10+ 도중 **규칙 반전**(1초 예고 후) · 예외 규칙("단, 안경 쓰면 반대").
- **승리**: 제한시간 안에 목표 장수(10 → 16)를 처리하고 실수 < 허용치. **실패**: 실수 3회 또는 시간 종료.
- **점수**: 정답 +100 · 콤보 배수 ×(1+0.1·연속, 상한 ×2) · 빠른 판단(<0.8초) +50 · 클리어 +300 + 남은 초×10. 오답은 감점 없이 콤보 리셋·실수 +1.
- **공정성**: 시드 생성기가 정답이 항상 하나로 정해지는 카드만 만들고, 같은 방향 연속 4장 초과 금지. 레벨이 오를수록 "복합 조건에 걸리는 까다로운 카드" 비율 증가(0% → 60%).
- **차별화**: 오답 시 **어느 속성 때문인지 하이라이트**(배우면서 빨라짐) · 규칙이 라운드마다 바뀌는 "규칙 도장" 연출 · 고나가 심판 역할로 반응.

### B. 고나의 아슬아슬 탑 (`tower`) — 균형 쌓기 (물리)
- **화면**: 접시 위에 쌓는 탑, 위쪽에 **다음 간식 2개**, 보관칸 1개(Hold).
- **조작**: 간식을 **드래그해 위치 지정 → 놓으면 낙하**. [회전] 버튼(90°), [보관] 버튼.
- **간식**: 6~8종(도넛·쿠키·바나나·케이크 조각·아이스콘·푸딩…). 모양(다각형 충돌체)·**무게**·마찰이 다름. 무게는 아이콘 표시(무거운 건 아래로).
- **정착 판정**: 속도 < ε 가 0.6초 지속되면 "놓임". 접시 밖으로 떨어지면 **낙하 1회**.
- **승리**: 목표 높이 선(6 → 14개 분량)에 닿고 1.5초 유지. **실패**: 낙하 3회 / 시간 종료 / 탑 전체가 쓰러짐(꼭대기 높이가 급락).
- **점수**: 놓을 때마다 높이×50 · **콤보**(기울기 < 임계 & 접촉면 ≥ 60% 로 안정 착지가 연속될수록 배수) · 클리어 +300 + 안정도 보너스.
- **난이도**: L1–3 무게중심(CoM) 점 표시 + 관대한 마찰 → L4–7 CoM 표시 끔 · 다음 간식 1개로 축소 → L8+ 바람 · L12+ 움직이는 접시.
- **차별화**: **무게중심 시각화**(학습 요소) · 무게별 배치 전략 · 콤보 달성 시 고나 응원으로 다음 간식 힌트 고스트.
- **기술**: 고정 시간 스텝(1/60) 물리. 직접 구현은 위험하므로 `matter-js`(MIT, 약 30KB gz, `tower` 청크에만 지연 로딩) 제안 — §8 승인 필요. 몸체 ≤ 25개 유지(저사양 Android 대응).

### C. 고나의 엉망진창 장난감방 (`toyroom`) — 정리 퍼즐 (턴제)
- **화면**: 선반 4~6줄(각 칸 수 3~6), 위에 **조건 카드**, 아래 이동 횟수 · 별 · 되돌리기.
- **조작**: 선반 **탭 → 맨 위(오른쪽 끝) 장난감 들림 → 다른 선반 탭 → 이동**(이동 1회 소모). 드래그는 후속 개선.
- **세트**: 한 선반에 같은 종류 장난감이 **setSize(3~4)개 연속**되면 사라져 **칸이 비어 공간 확보** + 콤보. 선반이 한 종류로만 꽉 찰 필요는 없음(자유도 ↑).
- **조건 카드(레벨별 1~3장)**: "무거운 곰은 맨 아래 칸만" · "공 위에는 쌓기 금지" · "빨간 장난감은 위쪽 선반만" · 잠긴 선반(세트 1개 완성 시 열림).
- **승리**: 모든 장난감 세트 완성 & 이동 횟수 한도 내. **실패**: 한도 소진 또는 **합법 수가 없는 교착**(자동 감지 → 즉시 실패 · 되돌리기 있으면 안내). 별 3개 = 한도 내 par 이하.
- **해결 가능 보장**: 완성 상태에서 **역방향으로 섞어 생성** → 풀이 길이 = par. 한도 = par + 여유(레벨↑ 시 감소). 낮은 레벨은 BFS 솔버 단위 테스트로 검증.
- **점수**: 세트 +100 × 체인(3수 이내 연속 완성) · 남은 이동 ×20 · 별 보너스.
- **시간**: 자유 플레이는 무제한, 챌린지는 여유 있는 상한(60→40초). `timeLimitSec(level, mode)` 로 모드별 선언.
- **차별화**: 단순 색 정렬이 아니라 "조건 카드 + 공간 확보" 구조 · 세트 완성이 곧 여유 공간이라는 리듬 · 타 게임의 튜브·병 구조·이름 미사용.

## 5. 공통 UI/사운드 방향
- 게임별 독립 UI·팔레트(예: 편가르기=심판석 오렌지, 탑=하늘 파랑, 장난감방=연보라 방), 공통 HUD 형태는 유지.
