## 2. 실제 작동 vs 보류
- **작동**: 위 전부. 단, **게임 플레이 기록이 쌓이는 경로는 Food 패치 적용 전이라 실제로는 비활성**(`FOOD_LINK='pending'`). 이 상태에서는 PLAY 가 기존 Food 주소 그대로 열리고(세션/`?gp` 없음), 섬 팝업·업적·미션·랭킹이 **"기록 연동 준비 중 / 게임 연동 대기"** 로 표시되며 가짜 기록·보상은 없다.
- **보류(승인 필요)**: ① Food 저장소 패치 적용 ② 온라인 랭킹 서버(Cloudflare 계정/D1) 연결 ③ 운영 배포 ④ 몬스터·보스 아바타 정식 에셋 ⑤ XP/코인/종합 랭킹 수치 확정(D7) ⑥ 비밀 복구 코드(D8).
- 보상/업적/미션은 **실제 앱 안의 행동**(출석·실행·화면 방문·상점)만 지금 작동. 게임 결과 기반 보상은 결과 수신(=Food 패치) 후에만 지급.

## 3. 게임 기록 연동 상태
수신부(세션·inbox·검증·반영·결과 화면)와 Food 쪽 SDK 가 **서로의 코드로 끝까지 검증**됨(`foodPatch.test.ts`: 시작→게임 오버/엔딩→inbox→게임천국 반영, 엔딩 다시보기 중복 방지, 일시정지 시간 제외, 저장 실패 재시도, 비활성 조건 no-op, 기존 키 불변). 실제 Food 와의 연결은 패치 적용 + `FOOD_LINK='live'` 두 가지만 남음(`food-patch/README.md`).

## 7. 발견·해결한 오류
1. **브라우저 localStorage 에는 `keys()` 가 없어 inbox 를 읽지 못함**(결과가 반영되지 않음) → 어댑터에 `key(i)` 기반 `keys()` 추가 (e2e 가 발견)
2. 결과 화면 하단 버튼이 393×636 에서 잘림 → 간격·점수 크기 조정(한 화면에 들어감)
3. 상점 미리보기에서 테두리/아바타가 잘림(초상 CSS 고정 크기) → 크기 규칙 정리
4. 알림 토스트가 업적 여러 개일 때 길게 쌓임 → 같은 종류 묶어 표시
5. 섬 팝업 문구 줄바꿈으로 높이 증가 → 문구 단축
6. 테스트 가정 오류(보상 코인·한도 값, 세션 시간)를 수정해 규칙에 맞게 검증

## 11. 안전한 미리보기 방법 (공개 배포/외부 연결 없이)
- 로컬: `npm ci && npm run build && npm run preview` → 브라우저에서 확인. 개발 서버 `VITE_DEV_SIM=1 npm run dev` 에서는 **설정 > 개발용 시뮬레이터**로 Food 결과(게임 오버/클리어)를 실제 수신 경로 그대로 주입해 결과 화면·보상·업적·도감을 체험할 수 있다(운영 빌드에는 포함되지 않음).
- 스크린샷: `docs/platform/full-shots/` · 자동 테스트: `npm test`, `node tools/platform-e2e*.cjs`.
- 공개 URL 미리보기가 필요하면(예: 비공개 아티팩트/임시 Pages) 외부 게시에 해당하므로 **승인 후** 진행.
