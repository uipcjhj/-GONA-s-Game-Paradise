# Food Adventure 실연동 검증 보고서

범위: 로컬 개발 서버(Paradise 라이브 빌드 + Food `claude/paradise-link` 개발 빌드)에서 **터치 입력을 보내는 봇이 실제 Food 를 플레이**(`tools/live-e2e.cjs`, `tools/food-bot.cjs`). 시뮬레이션 결과 주입이 아니다. 운영 URL 은 건드리지 않았고 `FOOD_LINK=live` 는 개발 빌드에서만 켰다.
**봇 플레이 ≠ 사람 플레이, Chromium 모바일 에뮬레이션 ≠ 실제 iPhone.** 실기기 항목은 아래 "미검증"에 분리했다.

클리어 플레이 요약: 13.1분, 사망 3회(모두 체크포인트 이어하기), 최종 4단계·3,870점. 판마다 결과 1건(게임 오버 3 + 클리어 1), 각 판 점수가 Food 화면 점수와 일치(3225→3250→3230→클리어 3870, 합산·이중 계산 없음), 엔딩 다시보기 후에도 결과 4건 그대로(중복 없음), 돌아가기 버튼이 엔딩 버튼과 겹치지 않음, 결과 화면(ADVENTURE CLEAR·4단계·XP/코인), 기록(플레이 4·클리어 1·최고 3,870 = Food 자체 최고), 업적·도감(가족 6·킁카·뽀뽀)·칭호, 하루 보상 한도, 새로고침 후 재표시 없음, 콘솔 오류 없음.

## 밸런스 검토 (봇 데이터만)
- 보상 한도(점수 상한 120/초, 200만, 이월 6만)는 **잠정값 유지.** 봇 한 번의 클리어(3,870점·13분)는 한도에 한참 못 미쳐 한도가 과하게 빡빡하지 않다는 것만 확인. 느슨함·치트 탐지력은 **사람 플레이 데이터가 없어 판단 불가** → 변경하지 않음.
- 클리어 보상(XP +175·코인 +80급, 레벨 1→4)은 첫 클리어 기준 체감 확인용. 최종 수치 확정(D7)은 사용자 승인 사항.

## 미검증 · 한계
1. **보스전 재도전**(`bossretry`): 시나리오는 첫 사망이 보스전일 때만 `보스전 다시` 분기를 실행한다. 이번 플레이에서 사망은 체크포인트 사망이었고 보스 사망은 재현하지 못해 **미검증**(체크포인트 이어하기는 검증됨). 보스전에서 죽도록 유도하는 테스트 훅이 필요.
2. 실제 iPhone Safari/인앱 브라우저 **수동 검증 미실시**(터치 지연·주소창 높이·백그라운드 복귀).
3. 봇은 한 가지 플레이 스타일. 사람의 일시정지·앱 전환·장시간 방치 시나리오는 단위/에뮬레이션 수준.
