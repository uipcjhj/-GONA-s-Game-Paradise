# 게임천국 홈 플랫폼 — 구현 결과 (브랜치 `claude/platform-home`)

> 진행 상황·다음 작업은 [MASTER_PROGRESS](MASTER_PROGRESS.md). 계약은 [GAME_RESULT_CONTRACT](GAME_RESULT_CONTRACT.md) (설계 그대로 구현, 아래 "계약과 달라진 점" 참고).

## 동작 흐름
`월드맵 → 섬 탭 → 팝업(내 기록·입장) → 입장(세션 발급, 게임 주소에 ?gp=세션) → 게임이 끝날 때 inbox 에 결과 1건 기록 → 게임천국 복귀(버튼·뒤로가기·탭 복귀·다음 접속) → 검증·적용·1회 저장 → 결과 화면(한 번만) → 월드맵`

## 코드 구조 (`src/platform/`) — 규칙은 전부 React 와 무관한 순수 함수(단위 테스트)
| 파일 | 역할 |
|---|---|
| `types.ts` `schema.ts` | 플레이어 데이터 **스키마 v2** · 검증(부가 구조가 깨져도 그 부분만 기본값) · 마이그레이션 체인(v1→v2) |
| `result.ts` | 결과 봉투 검증(형식·크기·버전·범위·시간·세션·플레이어·초당 점수) |
| `registry.ts` | 게임 등록부(결과 규칙, 하위 게임) — 새 게임은 한 항목 추가 |
| `records.ts` | 기록 갱신(최고점·동점 유지·단계·이 기기 TOP10·주간 최고) · 이전 기록 가져오기(1회) |
| `engine.ts` | `applyGameResult` — 중복 차단→기록→보상(일일 상한)→미션→업적·도감→원장. 입력 불변 |
| `inbox.ts` `session.ts` | inbox 수신(전부 적용→1회 저장→성공 후 삭제, 저장 실패 시 보존), 세션 발급·정리 |
| `progression.ts` `tuning.ts` | XP/레벨/코인 지급, **수치 표 하나**(임시값, 운영 전 승인 필요) |
| `achievements.ts` `missions.ts` `codex.ts` `shop.ts` | 업적 22 · 미션(일일 3/주간 3)·출석 · 도감 · 상점/장착 |
| `localRanking.ts` | **이 기기 순위**(주간/역대) — 다른 플레이어 순위가 아님 |
| `sdk/gp-sdk.ts` | 게임 쪽 SDK(의존성 없는 한 파일). Mini Game Land 가 사용, Food 용 사본은 `food-patch/` |
| `PlayerContext.tsx` | 상태·저장·수신 트리거(시작·pageshow·visibility·storage, Web Locks) |
| `backStack.ts` | 뒤로가기 레이어(이번에 이탈 버그 수정) |

## 화면
결과(`screens/Result`) · 프로필(통계·게임 기록·장착 꾸미기) · 랭킹(온라인 미연결 명시 + 이 기기 순위) · MORE: 업적/도감/미션·출석/상점/설정(진동·움직임 줄이기·백업/복원·이전 Food 기록 가져오기·초기화). 하단 MORE 에 받을 보상이 있으면 점 표시.

## 로컬로 되는 것 vs 서버가 필요한 것
- **로컬(구현됨)**: 모든 기록·XP·코인·업적·미션·도감·상점·꾸미기·백업/복원·이 기기 순위.
- **서버 필요(미구현)**: 다른 사람과 비교하는 주간/역대/종합 랭킹, 기기 간 동기화, 부정 방지. `services/ranking.ts` 인터페이스만 있고 `NullRankingProvider`(미연결). **가짜 이용자 기록은 어디에도 없음.**

## 한계(솔직하게)
- 결과는 같은 출처 localStorage 라 **조작 가능한 로컬 기록**. 형식·범위·시간·세션 검증으로 실수/단순 조작만 걸러냄. 온라인 랭킹에는 쓰지 않는다는 전제.
- 일일 보상은 **기기 시계(KST)** 기준 — 시계를 바꾸면 보상 반복 가능(소액·무가치 재화만, 시계가 과거로 가면 미션 갱신 안 함).
- Food 는 SDK 가 적용되기 전이라 **기록이 자동으로 쌓이지 않음**(섬 팝업에 "기록 연동 준비 중" 표시). 이전 최고 기록 가져오기만 가능.
- Sky Battle 은 게임이 없어 COMING SOON(등록부·결과 규칙만 준비).
- XP·코인·상한·일일 미션 수치, 이상치 한도는 임시값. 최종 아트가 아닌 임시 UI(CSS 색 테두리/배경, 아이콘). **실제 iOS Safari 미검증**(에뮬레이션만).
- 진동 설정은 저장만(게임천국이 쓰는 진동 없음, 각 게임 설정을 따름).

## 계약과 달라진 점
- `GameResultRule.scoreBurst` 추가: 클리어·시간 보너스처럼 한 번에 붙는 점수를 초당 점수 검사에 허용(실제 봇 플레이가 초당 한도에 걸려 발견).
- SDK 는 **주소의 `gp` 만** 신뢰(탭 기억 없음 — 단독 실행이 이전 세션에 기록되는 문제를 테스트가 발견).
- 부모 게임(`minigame-paradise`)은 서로 다른 미니게임 점수를 섞지 않아 **최고점 없음**(플레이·클리어·시간만 합산), 점수는 하위 게임별.
- 챌린지는 라운드별이 아니라 **한 번의 도전(목숨 소진/그만두기) = 1판**(subGame `challenge`), 한 라운드도 못 했으면 기록 안 함.
